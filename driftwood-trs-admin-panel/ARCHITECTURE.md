# Architecture — Driftwood TRS Admin Panel

See `TECH_STACK.md` for the full dependency list. This document covers code organization.

## Folder structure

```
src/
├── main.tsx                     # entry point — mounts MantineProvider + AppRouterProvider
├── routeTree.gen.ts              # AUTO-GENERATED by the TanStack Router Vite plugin — do not hand-edit
├── common/                       # cross-cutting code shared across features
│   ├── api/                      # axios-based API layer, one file per backend resource
│   │   ├── client.ts              # shared axios instance + getApiErrorMessage() helper
│   │   ├── auth.ts                # auth query/mutation options
│   │   ├── users.ts, documents.ts, aiPrompts.ts
│   │   └── index.ts                # barrel export
│   ├── auth/roles.ts              # hasAnyRole, requireRole, getRoleLabel
│   ├── contexts/index.tsx         # AppRouterProvider: QueryClientProvider + auth bootstrap + RouterProvider
│   ├── hooks/useUserStore.ts      # Zustand store for the current user
│   ├── pagination/                 # URL-search-param-driven pagination utilities
│   └── pdf/generateReportPdf.ts   # jsPDF report export
├── components/                    # shared, feature-agnostic UI
│   ├── Link.tsx
│   ├── pagination/                 # SortableTh, TablePagination
│   └── private-shell/              # app shell: header, navbar, layout
├── features/                      # feature/domain modules (components colocated with their domain)
│   ├── ai-prompts/components/PromptEditorModal.tsx
│   ├── documents/components/       # AnalystDocumentDrawer, DocumentsTable, ClassifyDocumentModal, ...
│   └── users/components/           # UserFormModal, UsersDirectoryTable, AccountProfileForm, ...
└── routes/                        # TanStack Router file-based routes
    ├── __root.tsx                  # root layout, RouterContext (queryClient)
    ├── _private/                    # authenticated-only layout (beforeLoad redirects to /login)
    │   ├── route.tsx                 # role-gated nav (admin/analyst/user)
    │   ├── dashboard.tsx, documents.tsx, profile.tsx, users.tsx, users_.$userId.tsx
    │   ├── admin/ai-prompts.tsx       # admin-only
    │   └── analyst/documents.tsx      # analyst-only
    └── _public/                      # unauthenticated layout (redirects to /dashboard if logged in)
        ├── route.tsx
        └── login.tsx, forgot-password.tsx, reset-password.tsx
```

## Data flow

- **Server state** (anything from the API) goes through TanStack Query. Each resource in `src/common/api/*.ts` exports query-key factories and query/mutation option objects — components call `useQuery(...)` / `useMutation(...)` with those options rather than building requests inline.
- **Client state** (things not owned by the server) is minimal — currently just the authenticated user profile, in a single Zustand store (`useUserStore`).
- **Auth bootstrap** happens once in `AppRouterProvider`: it fetches the user profile via `authQueryOptions.profile()` before rendering the router, so route guards always have a resolved auth state.

## Routing & access control

- File-based routing via `@tanstack/router-plugin`. Files under `_private/` and `_public/` are route-group layouts (the `_` prefix excludes the segment from the URL).
- `_private/route.tsx` runs a `beforeLoad` guard that redirects to `/login` if unauthenticated, and filters nav items by role.
- `_public/route.tsx` redirects to `/dashboard` if already authenticated.
- Role checks reuse `src/common/auth/roles.ts` (`requireRole`, `hasAnyRole`) both in route guards and in nav rendering, so the two never drift independently.

## Conventions

- Feature components live under `src/features/<domain>/components/`; only genuinely cross-feature UI goes in top-level `src/components/`.
- API calls never happen directly from components — always through a `src/common/api/*.ts` module's query/mutation options.
- Do not hand-edit `src/routeTree.gen.ts`; it's regenerated by the Vite plugin on every route file change.
